# Растровый редактор — практика 1

Эталонное решение первой практики темы «Растровый редактор»: каркас программы
с двумя режимами запуска. Изображения ещё нет, редактор помнит только имя файла.

## Что сделано

- Режим одной операции: `raster <файл> <операция>`. Программа печатает число
  аргументов и каждый из них, затем разобранные части (программа, файл,
  операция), выполняет операцию и завершается.
- Интерактивный режим: без аргументов программа принимает операции `info`,
  `help`, `quit` (и `exit`), пока не будет команды выхода или ввод не кончится.
- В начале работы печатается выбранный режим.
- Неизвестная операция в интерактивном режиме даёт подсказку и не завершает
  работу, в режиме одной операции — ненулевой код возврата.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/raster photo.ppm info     # одна операция
./build/raster                    # интерактивный режим
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## На что обратить внимание при разборе

**Один код операций на два режима.** `operation_execute` вызывается из обоих
режимов, отличается только источник слова. Вторая реализация той же операции
для другого режима — главная ошибка проектирования этого занятия.

**Число аргументов проверяется до обращения к ним.** При `argc == 2` элемент
`argv[2]` — нулевой указатель, и печать его как строки — неопределённое
поведение.

**Одно условие выхода из цикла.** Команда `quit` и конец ввода сводятся
к флагу `running`, поэтому у цикла нет `break` и выход виден в заголовке `while`.

**Два потока вывода.** Ошибки запуска, после которых программа завершается
с ненулевым кодом, идут в `stderr`, ответы на команды — в `stdout`. Так ошибку
видно, даже если обычный вывод перенаправлен в файл.

**Чтение строки.** Хвост слишком длинной строки дочитывается и выбрасывается,
иначе он стал бы следующей командой. Пустая строка — не ошибка, а пустая
операция.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
