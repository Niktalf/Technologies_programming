# Растровый редактор — практика 13

Продолжение проекта двенадцатой практики. Операция над пикселем стала
значением. Обход изображения написан в проекте один раз, а инверсия,
серое, яркость и контраст — это лямбды, переданные в него. На втором
обходе, с координатами, сделана виньетка. Всё, что умел редактор
на практике 12, осталось.

## Что сделано

**Типы операций** (`include/pixel_ops.hpp`):

```cpp
using PixelOp = std::function<Color(Color color)>;
using PositionOp = std::function<Color(Color color, int x, int y)>;
using PixelVisitor = std::function<void(Color color, int x, int y)>;
```

Операция получает старый цвет и возвращает новый. Сама изображение
не трогает — пишет в него обход.

**Функции высшего порядка:**

- `for_each_pixel(image, op)` — каждой точке новый цвет `op(цвет)`;
- `for_each_pixel_at(image, op)` — то же, с координатами точки;
- `visit_pixels(image, visit)` — обход только для чтения.

Все три сводятся к одному двойному циклу `for_each_point` в
`pixel_ops.cpp` — единственному на весь проект. На практике 12 таких
циклов было девять.

**Четыре фильтра — лямбды** в `make_filter`:

```cpp
[](Color c) { return c.inverted(); }                 // invert
[](Color c) { return c.to_gray(); }                  // gray
[parameter](Color c) { return c.brighten(parameter); }   // bright
[parameter](Color c) { ... }                         // contrast
```

`PixelFilter` больше не базовый класс для четырёх наследников. Это один
класс, который хранит имя и операцию. Классов `InvertFilter`, `GrayFilter`,
`BrightnessFilter` и `ContrastFilter` больше нет. Команды `invert` и
`bright` тоже передают лямбду прямо в `for_each_pixel`.

**Виньетка** (`vignette <процент>`) — на `for_each_pixel_at`: точка темнеет
пропорционально квадрату расстояния до центра. При 100 углы чёрные, центр
не меняется.

**Тот же обход вместо прежних циклов.** Генераторы узоров, обрезка,
поворот и масштаб обходят новое изображение и для каждой его точки берут
цвет из старого. Чтение PPM — операция, которая читает три канала
из файла. Запись PPM — `visit_pixels`. Размытие тоже на
`for_each_pixel_at`: ему нужны соседи, поэтому операция берёт координаты
и читает соседей из копии.

## Сравнение объёма кода

В строках разница невелика: 2040 строк на практике 12, 2117 здесь. Новые
строки — комментарии о лямбдах и захвате и виньетка, которой раньше
не было. Изменился не объём, а то, где что написано:

- двойных циклов по изображению было девять, теперь один;
- классов фильтров было семь, теперь четыре;
- новый попиксельный фильтр — одна строка в `make_filter`: имя и лямбда,
  без класса и без цикла.

Вывод: функция высшего порядка убирает не строки, а повторение. Ошибку
в обходе теперь можно сделать только в одном месте и исправить тоже в одном.

## Проверка

Сценарий из сорока команд практики 12 дал ровно тот же вывод. Все
одиннадцать записанных файлов совпадают байт в байт. В сценарии узоры,
`invert`, `bright`, обрезка, повороты на 90, 180 и 270, масштаб, цепочка
фильтров, `blur`, чтение текстового и двоичного файла. Оборванные P3 и P6,
P5 и значение больше максимума отвергаются так же, как раньше.

Виньетка 100 на белом изображении 5 на 5: углы 0, центр 255, края между
ними — 95, 127, 191, 223. Всё прогнано под санитайзерами адресов,
неопределённого поведения и утечек — без ошибок.

Цена `std::function`: изображение 4000 на 3000 с `blur`, `invert` и `gray`
обрабатывается за 2,1 с, на практике 12 — за 1,2 с. Каждая точка теперь
проходит через вызов функции, хранящейся в `std::function`: компилятор
не видит, что за ней, и не может встроить её в цикл. Эту цену снимают
шаблоны: тогда тип операции известен компилятору заранее.

## На что обратить внимание при разборе

**Лямбда без захвата и с захватом.** `[](Color c) { ... }` у инверсии —
по сути обычная функция. `[parameter](Color c) { ... }` у яркости — объект
с полем `parameter`. Для фильтра с параметром захват неизбежен.

**Захват по значению.** `make_filter` закончится раньше, чем фильтр
применят, и её переменная `parameter` исчезнет. Поэтому она захвачена
копией. Захват по ссылке, `[&parameter]`, оставил бы фильтр со ссылкой
в никуда.

**Захват по ссылке, где он безопасен.** `for_each_pixel_at` захватывает
`image` и `op` по ссылке: лямбда живёт только внутри вызова, а они —
дольше. Чтение PPM захватывает поток и `status` по ссылке по той же
причине.

**Операция возвращает цвет, а не пишет его.** Писать в изображение может
только обход. Поэтому операцию нельзя случайно применить «немного не к той
точке».

**Размытие — другой вид обхода.** Операции над одним цветом размытию мало,
ему нужны соседи. Он берёт координаты и читает соседей из копии исходного
изображения. Если читать из того же изображения, размытие «потечёт».

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.

превращается в нечитаемые символы.
