# Растровый редактор — практика 14

Продолжение проекта тринадцатой практики. Анализ изображения выражен через
фильтрацию, преобразование и свёртку. Новые команды: `analyze` — пять
запросов к изображению — и `levels` — автоматическое выравнивание уровней.
Всё, что умел редактор на практике 13, осталось.

## Что сделано

**Три операции** (`include/image_stats.hpp`). Изображение сначала становится
последовательностью цветов — `pixels(image)`, — а дальше:

| Операция | Функция | Алгоритм |
|---|---|---|
| filter | `select_pixels(colors, predicate)` | `std::copy_if` |
| map | `values(colors, value)` — число для каждой точки | `std::transform` |
| reduce | `mean`, `luminance_range`, `Histogram::range` | `std::accumulate` |

**Пять запросов — команда `analyze [порог]`:**

| Запрос | Как выражен |
|---|---|
| Средняя яркость | map в яркость, reduce суммой в `long long`, деление в `double` |
| Гистограмма каждого канала | один проход `std::for_each` по точкам — три счётчика за шаг |
| Доля точек темнее порога | filter по яркости, размер выборки к общему числу |
| Самый частый цвет | группировка словарём `unordered_map`, затем `std::max_element` |
| Наименьшая и наибольшая яркость | одна свёртка, в накопителе пара (минимум, максимум) |

Последовательности точек и яркостей строятся один раз на команду, и все пять
запросов берут их готовыми.

**`levels`** — выравнивание уровней по гистограмме.

- Для каждого канала `Histogram::lowest` и `highest` находят первое
  и последнее встреченное значение: `std::find_if` с начала и с конца
  массива.
- `for_each_pixel` растягивает канал так, чтобы этот диапазон стал
  0–255. Канал с единственным значением не трогается: деление на ноль.

**`minmax`** теперь — map и reduce. Цикл `Image::min_max` удалён;
`print_short` в `demo` тоже пользуется свёрткой.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/raster_editor
> size 64 48
> gen gradient
> contrast 30
> analyze 100
> levels
> analyze
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## Проверка

Градиент 64 на 48 после `contrast 30` тусклый — яркость от 90 до 166.
`levels` растягивает её снова до 0–255:

```
> analyze 100
Brightness from 90 to 166
> levels
Channel ranges before: red 90-166, green 90-166, blue 90-166
Levels stretched to 0-255.
> analyze
Brightness from 0 to 255
```

У исходного градиента гистограмма ровная — по 384 точки в каждой корзине.
Темнее 64 ровно четверть точек, средняя 127,03, а не 127: деление
в `double`. Порог 300 и `x` отвергаются.

Сценарий из сорока команд практики 13 вместе с `demo` дал ровно тот же
вывод, и файлы совпадают байт в байт. `analyze` и `levels` на изображении
3000 на 2000 вместе занимают 0,7 с. Всё прогнано под санитайзерами адресов,
неопределённого поведения и утечек — без ошибок.

## На что обратить внимание при разборе

**Начальное значение свёртки.** Для минимума — 255, верх диапазона.
С нулём минимум был бы нулём на любом изображении. Для максимума — 0.
Для суммы — `0LL`: яркость 255 на 8192 × 8192 точках — 17 миллиардов,
в `int` это не помещается.

**Деление в `double`.** `sum / size` в целых даёт 127 вместо 127,6.
Средняя — `static_cast<double>(sum) / size`.

**Гистограмма — один проход.** Свёртка `std::accumulate` с гистограммой
в накопителе копировала бы три массива по 256 чисел на каждую точку.
Поэтому гистограмму считает `std::for_each`, а лямбда пишет в неё
по ссылке. Это тот же проход без копий.

**Группировка словарём, а не вложенным циклом.** Самый частый цвет —
один проход с `++counts[цвет]`. Вложенный цикл «для каждого цвета
посчитать его по всему изображению» на 6 миллионах точек — 36 триллионов
сравнений.

**Предикат без побочных эффектов.** Предикат «темнее порога» только
сравнивает. Если бы он печатал или красил точку, результат зависел бы
от того, сколько раз его вызвал алгоритм.

**Равенство в самом частом цвете.** При равных счётчиках выигрывает
меньший упакованный цвет. Иначе ответ зависел бы от порядка обхода
хеш-таблицы.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.

в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
