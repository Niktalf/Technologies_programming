# Хранилище ключ-значение — практика 4

Продолжение проекта третьей практики: упорядоченный вывод и диапазонные запросы.

## Что сделано

- Модуль `range`: ключи собираются из хеш-таблицы, сортируются рекурсивным
  слиянием, границы диапазона находятся рекурсивным двоичным поиском.
- Новые команды:
  - `sorted` — все пары в порядке возрастания ключей;
  - `range <от> <до>` — пары с ключами в диапазоне, обе границы включены.
- Обе команды сообщают глубину рекурсии сортировки.
- Каждая команда — отдельная функция. Всё из практик 1–3 работает как прежде.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/kvstore
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## Проверка

```
> sorted
apple = 1
banana = 2
cherry = 4
fig = 5
pear = 3
Pairs total: 5, sort recursion depth: 4
> range banana cherry
banana = 2
cherry = 4
Pairs found: 2, sort recursion depth: 4
> range z a
The lower bound is greater than the upper one: the range is empty.
```

Пять краевых случаев из задания: пустое хранилище, диапазон целиком до всех
ключей, целиком после, границы совпадают с существующими ключами, начальная
граница больше конечной. Все дают верный результат. На 10 000 случайных ключах
порядок и содержимое диапазона сверены с Python.

## На что обратить внимание при разборе

**Нижняя и верхняя граница отличаются одним сравнением.** `lower_bound` ищет первый
ключ не меньше, `upper_bound` — первый строго больше. От этой разницы зависит,
войдёт ли правая граница в диапазон. На доске полезно поменять одно на другое
и посмотреть, как пропадает последний ключ.

**Лексикографический порядок.** `range b c` не включает `cat`: строка `cat` больше
строки `c`, потому что длиннее при общем начале.

**Сортировка на каждый запрос.** Хеш-таблица не хранит порядок, поэтому каждый
диапазонный запрос сортирует все ключи заново. На десяти тысячах это незаметно,
на миллионе — уже нет. Именно поэтому хранилища с диапазонными запросами держат
ключи в дереве, а не в хеш-таблице. Стоит обсудить это вслух: студент сам
почувствовал проблему.

**Указатели внутрь таблицы.** Модуль собирает указатели на ключи и значения
в ячейках, не копируя строки. Они действительны, пока таблицу никто не меняет.

**Неверный порядок границ проверяется дважды.** Команда `range` сообщает
о пустом диапазоне сама, но и `range_query` не полагается на вызывающего
и возвращает ноль: модуль не должен зависеть от того, проверил ли его кто-то снаружи.
