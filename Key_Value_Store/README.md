# Хранилище ключ-значение — практика 7

Продолжение проекта шестой практики: ключи и значения любой длины,
таблица растёт сама.

## Что сделано

- Ключ и значение лежат в куче по своей настоящей длине: ограничений
  в тридцать два и сто двадцать восемь байт больше нет.
- Когда заполненность переваливает за семьдесят процентов, таблица
  перестраивается вдвое большей, и все ключи раскладываются заново.
- Новые команды:
  - `close` — закрыть текущее хранилище: освободить все ключи, значения
    и таблицу. На его месте сразу открывается новое, пустое.
  - `stress <n> <скрипт>` — n раз создать хранилище, залить в него скрипт
    и закрыть.
- `stats` показывает и число перестроений, `bench` не ограничен вместимостью.
- Всё из практик 1–6 работает как прежде.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/kvstore
> genscript pairs100k.kv 100000
> script pairs100k.kv
> stats
> close
> genscript pairs10k.kv 10000
> stress 100 pairs10k.kv
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## На что обратить внимание при разборе

**Почему нельзя перенести ячейки по прежним номерам.** Номер зависит
от размера таблицы, и после удвоения он у всех ключей другой. Это тот же
вопрос, что на практике 3 при ручном перехешировании.

**Строки переносятся по указателю.** При перестроении ключи и значения
не копируются заново — переезжают только адреса. Строки удалённых ячеек
освобождаются сразу в `store_remove`, а указатели обнуляются, поэтому при
перестроении освобождается только старый массив ячеек. Хороший вопрос
на сдаче: что утекло бы, если бы `store_remove` только ставила пометку.

**Новое значение готовится до освобождения старого.** В `store_put` при
обновлении сначала делается копия нового значения, и только потом выбрасывается
прежнее. Обратный порядок теряет старое значение, если памяти не хватило.

**Рост по заполненности, а не по отказу.** Таблица растёт на семидесяти
процентах. Если ждать, пока места совсем не останется, поиск выродится
в перебор задолго до этого.

**Почему `stress` заливает скрипт молча.** Через обычное выполнение каждая
команда печатала бы «добавлено», и сто повторов дали бы миллион строк вывода.
Поэтому `stress` читает скрипт сам и выполняет только команды `put`.

**Подбор коллизии зависит от размера.** Команда `collide` теперь подбирает
ключи уже в той таблице, куда их положит: домашняя ячейка считается
по текущей вместимости.

**Предел длины — буфер чтения строки.** Хранилище принимает строки любой
длины, но команду читает `fgets` в буфер: 256 символов в интерактивном
режиме, 512 в скрипте. Строка длиннее обрезается с сообщением.

**Структура маленькая, но по значению не передаётся.** `sizes` показывает
32 байта вместо 2,7 МБ, но копия структуры делила бы с оригиналом одну
таблицу: удаление через одну копию оставило бы в другой висячие указатели.

превращается в нечитаемые символы.
