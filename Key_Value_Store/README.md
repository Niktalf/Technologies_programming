# Хранилище ключ-значение — практика 8

Продолжение проекта седьмой практики: библиотека, журнал на диске
и восстановление после аварии.

## Что сделано

- Хранилище оформлено библиотекой: публичный заголовок `../../Users/Никита/Downloads/Mobile Devices/kvstore/src/kvstore.h`
  не показывает ни хеш-таблицу, ни формат записи — только неполный тип
  `KvStore`, перечисление кодов ошибок `KvStatus` и операции.
- Данные переживают перезапуск: каждая операция дописывается в журнал
  в формате записи из практики 2, при открытии журнал перечитывается
  и индекс собирается заново.
- Оборванная или испорченная запись означает конец пригодных данных:
  всё после неё отбрасывается и отрезается от файла.
- У библиотеки два клиента: прежняя интерактивная программа и телефонный
  справочник `demo/phonebook.c`, который включает только публичный заголовок.
- Новые команды `open` и `close`; `sizes` из практики 5 показывает,
  что клиент не знает даже размера `KvStore`.
- Всё из практик 1–7 работает как прежде, только `put` отвечает `saved`:
  библиотека не сообщает, был ли ключ раньше.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build                         # библиотека kvlib, kvstore и phonebook
./build/kvstore put name "Ivan Petrov"      # одна команда — и выход
./build/kvstore get name                    # следующий запуск: значение на месте
./build/kvstore                             # интерактивный режим
> genscript pairs10k.kv 10000
> script pairs10k.kv
> stats
> close
> open store1.db
./build/phonebook book.db add Ivan +7-900-111-22-33
./build/phonebook book.db list
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений. Журналы двух хранилищ по умолчанию — `store1.db`
и `store2.db` в текущем каталоге. Первый можно заменить ключом:
`./build/kvstore -f book.db list`.

## На что обратить внимание при разборе

**Что видно снаружи.** В публичном заголовке объявлен только `typedef struct
KvStore KvStore;` — само устройство описано в файле реализации. Клиент
не может залезть внутрь даже случайно, и внутренности можно переписать
целиком, не трогая его. Это и есть смысл библиотеки.

**Сначала журнал, потом память.** В `kv_put` и `kv_delete` запись сперва
уходит в файл и только потом в таблицу. Если программа умрёт между этими шагами,
при следующем открытии запись прочитается из журнала. В обратном порядке
она бы пропала.

**Сброс на диск после каждой записи.** Без него при аварии потеряется
не последняя операция, а всё, что осело в буфере. Насколько это дорого
и когда можно иначе — тема практики 24.

**Повреждённый хвост.** Первая запись, которая не читается целиком или
не сходится по контрольной сумме, означает конец пригодных данных.
Чтение останавливается, и хвост отрезается: целые записи копируются
во временный файл, который становится на место старого.

Писать новые записи просто поверх хвоста нельзя. Новая запись обычно
короче мусора, остаток мусора будет прочитан при следующем открытии,
а при неудачном совпадении байтов — даже принят за запись. В стандартной
библиотеке C нет функции, обрезающей файл, поэтому хвост отрезается
переписыванием. Происходит это только после аварии.

**Ошибки при восстановлении не игнорируются.** Если при сборке таблицы
не хватило памяти, база не открывается вовсе: открыть её наполовину
значило бы молча потерять часть данных.

**Внутреннее связывание.** Всё, что в `kvstore.c` не входит в интерфейс, —
`append`, `read_record`, `apply_record`, `recover`, `cut_tail` — объявлено
`static`: из других файлов эти функции не видны и не вызываются.

**Открытие без цепочки освобождений.** `create` выделяет структуру через
`calloc`: все указатели в ней сразу нулевые. Поэтому на любой стадии
неудачного открытия достаточно позвать `kv_close` — он закрывает и освобождает
только то, что успели открыть и выделить.

**Неполный тип не скопировать.** Команда `sizes` из практики 5 вернулась
в новом виде: клиент не знает даже размера `KvStore`, поэтому передать
хранилище по значению или скопировать его просто не получится — только
указатель.

**Демонстрации отдельно от клиента.** `bench`, `collide` и `record`
показывают внутреннее устройство, поэтому работают с таблицей и форматом
записи напрямую. Они вынесены в `demos.c`: остальная программа знает
только публичный заголовок.

**Удаление — это запись.** Надгробие попадает в журнал как обычная запись,
только с другим флагом. Поэтому журнал всегда растёт, даже когда данных
становится меньше. Доля мусора уже считается — по ней на практике 15
будет запускаться уплотнение.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.

в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
