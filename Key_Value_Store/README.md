# Хранилище ключ-значение — практика 6

Продолжение проекта пятой практики: кавычки, экранирование и скрипты.

## Что сделано

- Модуль `parser`: разбор строки на слова с учётом кавычек и обратной косой
  черты. Значение с пробелами берётся в кавычки, кавычка внутри значения
  пишется как `\"`.
- Модуль `script`: выполнение команд из файла с пропуском комментариев
  и пустых строк и с номером строки при ошибке.
- Новые команды: `script <файл> [stop]` и `genscript <файл> <n>`.
- Каждая команда возвращает `CLI_OK` или `CLI_ERROR`, выход — `CLI_QUIT`.
- Всё из практик 1–5 работает как прежде.

В комплекте три скрипта: `demo.kv` — рабочий пример, `broken.kv` — с незакрытой
кавычкой и командой без значения, `pairs1000.kv` — тысяча пар, записанная
командой `genscript pairs1000.kv 1000`.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/kvstore
> script demo.kv
> put quote "he said \"yes\""
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений. Скрипты лежат рядом с `../../Users/Никита/Downloads/Mobile Devices/kvstore/CMakeLists.txt`, поэтому запускайте

## На что обратить внимание при разборе

**Автомат из трёх состояний.** Разбор — это состояния «вне слова», «внутри кавычек»
и «сразу после обратной косой черты». Нарисовать их на доске стоит до того,
как писать код.

**Два указателя в одной строке.** Слово очищается от кавычек прямо в строке:
один указатель читает, другой пишет, и пишущий всегда отстаёт. Чтение одного
слова вынесено в `read_word`, которая получает оба указателя по адресу
и сдвигает их. Поучительная ошибка: если поставить завершающий ноль в тот самый
пробел, на который ещё смотрит читающий указатель, разбор закончится на первом
слове. Сначала шагаем через разделитель, потом ставим ноль. Ошибка тихая:
программа работает, просто команда теряет аргументы.

**Номер строки.** Без него искать ошибку в скрипте на тысячу строк невозможно.
Ошибкой считается не только неразобранная строка, но и команда, которая
не выполнилась: неизвестная или без обязательного аргумента. Поэтому
`cli_execute` возвращает не «продолжать или нет», а один из трёх кодов:
`CLI_QUIT`, `CLI_OK`, `CLI_ERROR`. «Ключ не найден» — это ответ, а не ошибка,
и скрипт из-за него не прерывается.

**Сообщения об ошибках идут в стандартный вывод.** Если писать их в поток
ошибок, при выполнении скрипта они перемешаются с обычным выводом не в том
порядке: у двух потоков разная буферизация.

**Длинная строка в скрипте.** Хвост дочитывается, иначе он стал бы отдельной
командой с другим номером строки.

**Скрипт останавливается по флагу.** Команда выхода и первая ошибка в режиме
`stop` сводятся к флагу `running` в условии цикла чтения. Разбор и выполнение
одной строки вынесены в `run_line`, итоги собираются в структуру `ScriptReport`.

**Код возврата в режиме одной команды.** `kvstore get` без ключа завершается
с кодом 1, `kvstore get x` для отсутствующего ключа — с кодом 0: ответ
«не найдено» — не ошибка.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
