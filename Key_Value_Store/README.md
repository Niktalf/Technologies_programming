# Хранилище ключ-значение — практика 13

Продолжение проекта двенадцатой практики. У хранилища появился обход
с колбэком: клиент передаёт функцию, она вызывается для каждой пары и может
остановить обход. Метод `pairs()`, копировавший все пары в вектор, удалён.
Все команды, перебиравшие пары, переписаны через обход. Всё, что умела
программа на практике 12, осталось.

## Что сделано

**Тип функции обхода** — в публичном заголовке `include/kvstore.hpp`:

```cpp
using Visitor = std::function<bool(const std::string& key, const std::string& value)>;
```

Функция получает ключ и значение константными ссылками на строки внутри
хранилища. Возвращает `true` — продолжать, `false` — остановиться.

**Обход.** `Engine::for_each(visit)` — чисто виртуальный, у каждого движка
свой цикл по таблице. Цикл идёт, пока `visit` отвечает `true`: на ответе
`false` он кончается, и остальные пары не перебираются вовсе. Метод
возвращает, сколько раз был вызван `visit`.

**Обход диапазона.** `Engine::for_each_in_range(from, to, visit)` написан
в базовом классе через `for_each`. Поэтому он одинаков для обоих движков
и согласован с полным обходом: это те же пары, отобранные по ключу.
Остановка тоже работает. Порядок пар не обещан ни там, ни там:
хеш-таблица порядка не знает.

**Публичный интерфейс.** `KvStore::for_each` и `KvStore::for_each_in_range`
пришли на смену `pairs()`. Наружу не уходит ни таблица, ни копия пар.

**Команды консоли через обход:**

- `list` — пары; `keys` — только ключи.
- `count` — сколько пар насчитал обход. Число сверяется с размером таблицы.
- `prefix <начало> [n]` — пары с ключом на это начало. С `n` обход
  останавливается, найдя `n` пар, и печатает, сколько пар успел перебрать.
- `sorted` и `range` собирают пары для сортировки тоже обходом.

**Демонстрационные программы.**

- Справочник: `list` и новая операция `prefix <начало имени>`. Поиск
  по началу имени сделан через обход — без доступа к таблице и без новой
  операции в библиотеке.
- Счётчик посещений считает итог обходом.

**Общий набор проверок** — теперь 19 проверок, обе новые проходят
на обоих движках:

- функция, ответившая `false` на первой паре, вызвана ровно один раз;
- обход диапазона дал ровно те пары полного обхода, что лежат в границах.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
ctest --test-dir build
./build/key_value_sore
> script demo/pairs1000.kv
> prefix key 3
> count
./build/key_value_sore_phonebook book.db prefix An
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## Проверка

Сценарий из тридцати команд практики 12 дал тот же вывод, кроме порядка
строк `list`. Журналы совпадают байт в байт.

На базе из 1008 пар `prefix key 3` нашёл три пары и перебрал ровно три.
`prefix user 2` нашёл две и остановился на 532-й паре из 1008. `count`
насчитал 1008 при размере 1008. `ctest` — 19 проверок на каждом движке,
все `ok`. Всё прогнано под санитайзерами адресов, неопределённого поведения
и утечек — без ошибок.

## На что обратить внимание при разборе

**Отдать данные, не отдавая структуру.** `pairs()` на практике 12 копировал
всю таблицу в вектор. Обход не копирует ничего: функция получает ссылки
на строки внутри таблицы на время вызова.

**Остановка — по-настоящему.** В цикле обхода условие `going && ...`:
после `false` цикл кончается. Неправильно было бы перебрать всё
до конца и просто не вызывать функцию — на миллионе пар это миллион
лишних шагов.

**Колбэк не должен менять хранилище.** Вставка в хеш-таблицу посреди
обхода может её перестроить, и обход пойдёт по освобождённой памяти.
Это записано у `Visitor`. Проверить это хранилище не может.

**Захват по ссылке в `prefix`.** Лямбда захватывает `start` и `found`
по ссылке: она живёт только внутри вызова `for_each`, а переменные — до
конца метода. Через `found` лямбда сообщает наружу, сколько нашла.

**Чего не хватает колбэку.** Обходом не сравнить две базы поэлементно:
темп задаёт хранилище, и в одном обходе нельзя «шагнуть» сразу по двум
базам. Так же нельзя прерваться, сделать что-то другое и продолжить
с того же места. Это умеет итератор: клиент сам решает, когда
взять следующий элемент. Цена — итератор раскрывает больше о том, как
устроено хранилище, и ломается, если хранилище меняют, пока он жив.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
