# Хранилище ключ-значение — практика 3

Продолжение проекта второй практики: поиск перебором заменён хеш-таблицей.

## Что сделано

- Хеш-таблица на 16 384 ячейки с открытой адресацией и линейным пробированием.
- У ячейки три состояния: пусто, занято, удалено.
- Интерфейс модуля `store` сохранился, поэтому команды `put`, `get`, `del`
  переписывать не пришлось. Перебор пар — через функцию обхода `store_for_each`.
- Новые команды:
  - `stats` — заполненность, число ключей не в своей ячейке, самая длинная цепочка проб;
  - `bench [n]` — замер поиска через хеш против перебора на n ключах;
  - `collide` — подбирает два ключа с одной ячейкой, удаляет первый и ищет второй.
- Команды практик 1–2 работают как прежде.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/kvstore
> bench 10000
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## Проверка

```
> collide
Keys a0 and a59909 fall into the same cell 14070.
Deleted a0.
Key a59909 found: second
> bench 2000
Keys: 2000
Hash:    found 2000 in 0.0004 s
Linear:  found 2000 in 0.2039 s
Hash is 491 times faster
```

Время зависит от машины. Отдельный тест заполняет таблицу до отказа: отказ
наступает ровно на ёмкости, поиск отсутствующего ключа в полной таблице
не зависает, после удаления каждого второго ключа ни один из оставшихся
не потерялся, удалённые ячейки занимаются повторно.

## На что обратить внимание при разборе

**Три состояния ячейки.** Главная мысль занятия. Команда `collide` показывает,
что второй ключ находится после удаления первого. Стоит на доске заменить в
`store_remove` пометку «удалено» на «пусто» и запустить `collide` снова: второй
ключ потеряется.

**Беззнаковый хеш.** Остаток от деления отрицательного числа даёт отрицательный
номер ячейки.

**Маска вместо остатка.** Ёмкость — степень двойки, поэтому номер ячейки
берётся побитовым И. Это связывает занятие с битовыми операциями второй практики.

**Ограничение числа проб.** Без него поиск отсутствующего ключа в полной таблице
не закончится.

**Скучивание.** На последовательных ключах при заполнении 61% самая длинная цепочка
проб — несколько сотен ячеек. Это не ошибка, а свойство линейного пробирования,
и хороший повод поговорить о том, почему заполненность держат ниже.

**Обход через функцию.** Порядок ячеек хеш-таблицы произвольный, и отдавать
наружу номер ячейки бессмысленно. Поэтому перебор пар теперь делается функцией
`store_for_each`, которой передаётся функция посещения.

**Цикл до пустой ячейки.** В `store_put` условие цикла проб содержит обе причины
остановки — исчерпаны пробы или встретилась пустая ячейка, — поэтому после цикла
видно, почему он кончился, без `break`. По той же схеме `collide` перебирает
кандидатов, пока не найдёт совпадение.

**Замер через указатель на функцию.** `search_all` принимает функцию поиска,
и один и тот же цикл замеряет и хеш, и перебор.
