# Подземелье — практика 11

Продолжение проекта десятой практики. Все поля закрыты, у каждого класса
записан инвариант, отрисовка вынесена из карты в отдельный класс, у монстров
появился статический счётчик. Всё, что умела игра на практике 10, осталось.

## Что сделано

Инвариант каждого класса записан комментарием над классом:

| Класс | Инвариант |
|---|---|
| `Hero` | `hp_max > 0`, `0 <= hp <= hp_max`, включены только биты известных состояний |
| `Monster` | `0 <= hp <= START_HP` |
| `MonsterList` | все монстры живы, никакие два не стоят в одной клетке |
| `Map` | пустая 0 на 0 либо: размеры в допустимых пределах, ровно `ширина * высота` клеток, каждая — `# . $ >`, старт внутри карты и не стена |
| `Game` | герой и монстры внутри карты не в стене, монстр не стоит на герое |
| `ExitSearch` | пометки по размеру обойдённой карты, счётчики согласованы с ними |

Каждый инвариант устанавливает конструктор и сохраняет каждый изменяющий
метод:

- `Hero(x, y, hp)` при `hp <= 0` бросает `std::invalid_argument`.
- `take_damage` с отрицательным уроном ничего не делает.
- Неверный номер состояния — `std::out_of_range`. Раньше он читал память
  за концом массива имён.
- `place_at` спрашивает карту и не ставит героя в стену.
- `Map::set_tile` отвергает клетку вне карты, чужой символ и стену
  на старте. `Map::clear` возвращает старт в клетку (1, 1).
- `MonsterList::add` не селит второго монстра в занятую клетку.
- `MonsterList::hit` бьёт и сам убирает погибшего монстра. Изменяемой
  ссылки на монстра список больше не отдаёт: на практике 10 игра била
  монстра сама и сама должна была не забыть его убрать.

Лишние методы доступа убраны: геттера золота нет, сеттеров нет ни одного.
`Map::trace` было открытым статическим полем — теперь оно закрыто
и меняется методом `Map::set_trace`.

Отрисовку делает новый класс `MapView`. Карта больше ничего не выводит
на экран, `Hero::look` тоже нет. `MapView` пользуется только открытыми
методами: размеры, символ клетки, координаты героя, поиск монстра.

`Monster` получил конструктор вместо статического `Monster::at` и статический
счётчик `Monster::created_count()`. Команда `monsters` печатает его последней
строкой. Почему счётчик статический, объяснено в `monster.hpp`.

Опыт 7 в `demo` пробует нарушить инварианты открытыми вызовами.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/dungeon demo                # опыты 1-6 со временем жизни, 7 - с инвариантами
./build/dungeon levels/cave.txt     # уровень из файла
./build/dungeon                     # спросит размер и зерно, построит случайный уровень
```

Режим `demo` открывает файлы из `levels/`, поэтому его нужно запускать
из папки проекта.

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

```
  Hero(1, 1, -5): rejected - hero health must be positive
  take_damage(-100): health 20 / 20
  take_damage(1000): health 0, not negative
  set_state(40): rejected - no such hero state
  set_tile with 'X': rejected

  a second monster in the same cell: rejected

```

Сценарий из пятидесяти команд на уровне `40 15 7` (шаги, предметы, урон,
состояния, `spawn`, `check`, атаки до гибели монстра, `level` с рабочим,
испорченным и отсутствующим файлом) и все уровни из `levels/` дают тот же
вывод, что практика 10. Добавилась одна строка в ответе на `monsters`:
`Monsters created since the start: N`. Всё прогнано под санитайзерами адресов,
неопределённого поведения и утечек — без ошибок.

## На что обратить внимание при разборе

**Инвариант — утверждение, а не пожелание.** «Поля заполнены правильно» —
не инвариант. `0 <= hp <= hp_max` — инвариант: его можно проверить одной
строкой в любой момент.

**Где проверяется инвариант.** В конструкторе и в каждом изменяющем методе.
Проверка только в сеттере пропускает объект, созданный с неверными
аргументами.

**Чей это инвариант.** «Герой стоит не в стене» — не инвариант героя: он
не знает карты. Это инвариант игры, которая владеет и героем, и картой.
Отсюда `place_at(map, x, y)`: герой спрашивает карту.

**Ссылка на внутренности отменяет защиту.** На практике 10
`MonsterList::at` отдавал `Monster&`, и любой код мог ударить монстра,
не убрав мёртвого. Тогда инвариант «все монстры живы» держался бы
на дисциплине каждого вызывающего. Теперь изменяющий доступ один — `hit`.

**Геттер не на каждое поле.** Геттер и сеттер на каждое поле — те же
открытые поля. Геттер золота удалён: его никто не читал.

**Разделение без дружественности.** `MapView` не `friend` карты. Иначе
он зависел бы от того, как карта хранит клетки, и разделение было бы
фиктивным.

**Статическое поле — одно на класс.** `created_count_` существует, даже
когда монстров нет. Копии, которые делает вектор, его не увеличивают:
у `Monster` копирующий конструктор создан компилятором, а счётчик растёт
только в `Monster(x, y)`.

**Открытое статическое поле — тоже открытое поле.** `Map::trace` закрыт
по той же причине, что и обычные поля.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
