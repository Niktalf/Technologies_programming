# Подземелье — практика 2

Продолжение проекта первой практики: характеристики героя, битовые флаги
состояний, приведение типов.

## Что сделано

- У героя есть здоровье (текущее и максимальное), сила атаки, золото и глубина
  этажа. Тип каждой характеристики обоснован комментарием в `../../Users/Никита/Downloads/Mobile Devices/dungeon/src/game.c`.
- Шесть состояний — отравлен, ослеплён, невидим, окаменел, горит, спит —
  хранятся в одной беззнаковой переменной, по биту на состояние.
- Новые команды:

| Команда | Что делает |
|---|---|
| `status` | характеристики, процент здоровья двумя способами, активные состояния словами |
| `hit N` | отнимает N единиц здоровья, ниже нуля здоровье не опускается |
| `on <состояние>` | включает состояние |
| `off <состояние>` | выключает состояние |
| `toggle <состояние>` | переключает состояние в противоположное |

Состояния в командах называются `poisoned`, `blinded`, `invisible`,
`petrified`, `burning`, `asleep`. Команды практики 1 работают как прежде.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/dungeon
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## На что обратить внимание при разборе

**Обоснование типов.** Записано комментарием у каждой переменной в `game.c`.
Главное: здоровье знаковое. Урон вычитается, и у беззнакового типа результат
меньше нуля превратился бы в огромное положительное число.

**Три операции над битом.** Установка — `states | mask`, снятие —
`states & ~mask`, переключение — `states ^ mask`. Снятие через «ИЛИ»
вместо «И с инверсией» — частая ошибка: бит при этом только ставится.

**Проверка бита.** `states & mask` равно самой маске, а не единице.
Для бита номер 4 это 16, и сравнение с единицей ложно. Сравнивать нужно
с нулём.

**Приведение до деления.** `hp / hp_max * 100` — целочисленное деление,
и при неполном здоровье получается 0. `(double)(hp / hp_max)` тоже не поможет:
делить целые уже поздно. Приводить нужно делимое до операции.

**Ширина в `%9d`.** Число из девяти цифр всегда помещается в `int`,
а длиннее `scanf` не прочитает. Без ширины ввод `99999999999` дал бы
неопределённое поведение.

**Одна таблица названий.** Массив `STATE_NAMES` упорядочен по номерам битов,
поэтому индекс найденного слова сразу даёт номер бита, а маска — `1u << i`.
Одно и то же слово служит и аргументом команды, и текстом в выводе.

**Остаток строки.** После неудачного чтения числа нечисловые символы
остаются во входном потоке. Функция `skip_rest_of_line` дочитывает строку
до конца, иначе мусор стал бы следующей командой.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
