# Подземелье — практика 8

Продолжение проекта седьмой практики: структуры, единые коды ошибок,
загрузка уровня из текстового файла, разбиение на модули.

## Что сделано

**Структуры.** `Hero` — все характеристики героя и сумка. `Monster` —
координаты и здоровье. Список монстров стал одним массивом структур
вместо двух параллельных массивов. `Map` — блок клеток и размеры. `Game` —
карта, монстры, герой и счётчик ходов. Обработчики команд получают адрес
`Game`: у `handle_command` было пятнадцать параметров, стало три.

**Коды ошибок.** Перечисление `Status`: успех, файл не найден, повреждённый
формат, нехватка памяти, недопустимый размер. Его возвращают все функции,
которые могут не справиться: создание карты, добавление монстра, проверка
достижимости, загрузка уровня. Ответ они отдают через выходные параметры.

**Уровень из файла.** `./build/dungeon levels/cave.txt` при запуске или
команда `level <файл>` во время игры. Формат описан в `../../Users/Никита/Downloads/Mobile Devices/dungeon/src/level.h`: карта
символами, `@` — герой, `M` — монстры. Неудачная загрузка не трогает
текущую игру.

Без аргумента игра, как раньше, спрашивает размер и строит случайный уровень.

Новые команды:

| Команда | Что делает |
|---|---|
| `level <файл>` | загрузить уровень из файла поверх текущего |
| `sizes` | размеры структур и указателя на `Game` |

Команды `addr` (практика 5) и `stacktest` (практика 4) остались в своих
архивах: они показывали устройство памяти и к игре не относятся.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/dungeon levels/cave.txt
./build/dungeon
40 15 7
> level levels/windows.txt
> level levels/ragged.txt
> sizes
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

Если файл уровня, заданный при запуске, не загрузился, сообщение уходит
в поток ошибок, и программа завершается с кодом 1. Ошибка команды `level`
во время игры — обычный ответ на команду, игра продолжается.

| Файл | Результат |
|---|---|
| `cave.txt` | загружен: 30 на 11, четыре монстра, выход достижим |
| `windows.txt` (концы строк `\r\n`) | загружен так же, как с `\n` |

| `small.txt` (три строки) | `invalid size` |
| `wide.txt` (130 символов) | `invalid size (line 1)` |
| `ragged.txt` (строки разной длины) | `corrupted format (line 3)` |
| `badchar.txt` (символ `X`) | `corrupted format (line 3)` |
| `nohero.txt` (нет `@`) | `corrupted format` |
| несуществующий файл | `file not found` |

Каждый файл проверен и при запуске, и командой `level` поверх уже открытой
игры. Случайный уровень, все команды, бой с монстром, `stress 50`,
выход по `quit`, по смерти героя и по концу ввода прогнаны под санитайзерами
адресов, неопределённого поведения и утечек — без ошибок.

## На что обратить внимание при разборе

**Освобождение одно на все ветки.** В `level_load` каждый шаг выполняется,
только если предыдущие удались, а при неудаче освобождается всё сразу.
Три выделения памяти и пять видов ошибок — и ни одной утечки, без повторения
`free` в каждой ветке.

**Состояние меняется только при успехе.** Уровень читается во временные
переменные. Прежние карта и монстры освобождаются, лишь когда новый уровень
прочитан и проверен целиком.

**Концы строк.** В Windows строка кончается на `\r\n`, в Linux на `\n`.
`strip_line_end` убирает оба символа, иначе строки файла из Windows были бы
на символ длиннее, а последний символ `\r` оказался бы «чужим».

**Структура по адресу, а не по значению.** `sizes` показывает: `Game` весит
112 байт, указатель на неё — 8. Функция, получившая `Game` по значению,
меняла бы копию, и ход игрока бы пропал.

**Каждой функции — только нужная часть.** `print_status` получает
`const Hero *`, `command_use` — `Hero *`, а не всю игру. По параметру видно,
что функция читает и что меняет.

**Выравнивание.** `sizeof(Hero)` больше суммы размеров полей: после
однобайтового `attack` компилятор вставляет пропуск, чтобы `gold` начинался
с адреса, кратного четырём.

**Указатель на элемент списка.** В `command_attack` адрес монстра живёт три
строки: удаление из списка или его рост переносят элементы, и адрес
перестаёт быть верным.

**Заголовки — только объявления.** Определения функций лежат в `.c`.
Если положить определение в заголовок, который включают два файла,
компоновщик увидит функцию дважды. Все заголовки защищены от повторного
включения.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.

в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
