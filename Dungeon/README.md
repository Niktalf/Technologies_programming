# Подземелье — практика 5

Продолжение проекта четвёртой практики: указатели. Функции получают адреса
и меняют состояние игры напрямую.

## Что сделано

- Глобальных переменных больше нет. Карта и характеристики героя — локальные
  переменные `game_run`, а функции получают их адреса:

| Функция | Что получает по адресу |
|---|---|
| `hero_move(map, &x, &y, direction)` | координаты; возвращает признак успеха, координаты меняет сама |
| `hero_damage(&hp, amount)` | здоровье |
| `hero_pick_gold(map, x, y, &gold)` | золото |
| `map_cell_info(map, x, y, &tile, &walkable)` | два результата сразу: символ клетки и проходимость |
| `reach_exit(map, x, y, &cells, &depth)` | итоги проверки вместо отдельных функций практики 4 |

- Новые команды: `cell` — что лежит под героем и проходима ли клетка,
  `addr` — адреса переменных из разных областей памяти.
- Всё из практик 1–4 работает как прежде.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/dungeon
> cell
> addr
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений. Сборка `cmake` без типа сборки идёт без оптимизации,
и `addr` честно показывает, что кадр вызванной функции лежит ниже кадра
вызывающей. В сборке `-DCMAKE_BUILD_TYPE=Release` компилятор встраивает мелкие
функции в вызывающую, и их локальные переменные оказываются в одном кадре.

## На что обратить внимание при разборе

**Почему имя массива ведёт себя как адрес.** Объяснено комментарием
в `map.h`. Коротко: в выражении имя массива превращается в адрес первого
элемента, а первый элемент двумерного массива — строка. Поэтому функция
получает указатель на строку, а не копию карты, и `&` не нужен.

**Функция, получившая копию, меняет копию.** Если объявить
`hero_damage(int hp, int amount)`, программа соберётся и даже напечатает
урон, но здоровье героя не изменится.

**`*hp - amount` и `*hp++`.** У постфиксного `++` приоритет выше, чем
у разыменования: `*hp++` сдвигает указатель и читает соседнюю память.
Нужно `++*hp` или `(*hp)++`.

**Проверки на нулевой указатель.** Во всех функциях, принимающих адрес,
кроме `visit` в `reach.c`: она статическая и вызывается только из
`reach_exit`, которая передаёт ей адреса своих локальных переменных.

**Обнуление локального массива.** Массив пометок в `reach_exit` объявлен
с инициализатором `{ { 0 } }`: элементы, для которых значение не указано,
становятся нулями. Без инициализатора локальный массив содержал бы мусор.

**Статическая переменная в функции.** `calls_here` объявлена внутри
`print_addresses`, но лежит рядом с глобальной `addr_calls`, а не в стеке,
и сохраняет значение между вызовами.

**Длинный список параметров.** У `handle_command` их одиннадцать. Так
выглядит код, в котором связанные данные ещё не собраны в структуру.
Так оставлено намеренно: на практике 8 герой станет одной структурой,
и список сократится. Сами ветки команд вынесены в функции `command_...`,
чтобы `handle_command` только выбирала команду.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
