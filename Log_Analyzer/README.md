# Анализатор логов — практика 3

Продолжение проекта второй практики: журнал стал массивом разобранных записей.

## Что сделано

- Строки журнала разбираются на поля — время, уровень, модуль, текст —
  и хранятся массивом фиксированного размера на 10 000 записей.
- Испорченные строки считаются и не прерывают загрузку; пустая строка
  испорченной не считается; черта внутри сообщения сохраняется.
- Статистика по уровням, часам и модулям считается за один проход по массиву.
- Генератор тестовых журналов с воспроизводимым зерном.
- Новые команды: `load <файл>`, `gen <файл> <число> [зерно]`, `stats`, `hours`,
  `modules`. Программу можно запустить без файла и загрузить журнал потом.
- Фильтр уровней из практики 2 действует на `head`, `tail` и `count`.
  Кольцевой буфер из практики 1 больше не нужен: все записи и так в памяти.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/logan
> gen test.log 12000 42
> load test.log
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## Проверка

```
> gen test.log 12000 42
Created test.log: 12000 lines, seed 42
> load test.log
File: test.log
Lines: 12000, records: 10000
Records that did not fit into memory: 2000 (capacity 10000)
> stats
  DEBUG    2958   29%
  INFO     4050   40%
  WARN     1494   14%
  ERROR    1217   12%
  FATAL     281    2%
```

Файл на миллион строк загружается с сообщением, что 990 000 записей
не поместились в массив: так и должно быть до практики 7. Набор испорченных
строк — без разделителей, с тремя полями вместо четырёх, с неизвестным уровнем,
с тринадцатым месяцем, с пустым модулем — отсеивается целиком.

## На что обратить внимание при разборе

**Три поиска разделителя.** `parse_line` ищет вертикальную черту ровно трижды.
Разбиение по всем чертам подряд потеряет хвост сообщения, в котором черта встречается.
Генератор специально создаёт такие сообщения.

**Вместимость до записи.** Переполнение массива проверяется до записи элемента.

**Один проход на всю статистику.** `stats_collect` считает уровни, часы и модули
одним циклом. Пять проходов ради пяти показателей — типовая ошибка.

**Проценты и столбики.** Умножение до деления, в целых числах. Гистограмма по часам
масштабируется по максимуму, и при пустом журнале деления на ноль нет.

**Генератор с зерном.** Одинаковое зерно — одинаковый файл. Время записей случайное
и не упорядочено: на практике 4 это пригодится.

**Порядок вычисления аргументов.** В генераторе каждое случайное значение берётся
отдельной инструкцией, а не прямо в аргументах `fprintf`. Порядок вычисления
аргументов функции в C не определён: GCC обычно идёт справа налево, другие
компиляторы — слева направо, и при одном зерне файлы получились бы разными.

**Статический журнал.** Массив весит около трёх мегабайт, в стеке функции
он бы не поместился. Статистика, наоборот, весит несколько килобайт
и заводится локальной переменной только на время команды.

**Одна функция на команду.** Цикл `shell_run` только выбирает команду,
а `stats`, `hours` и `modules` разделяют одну функцию `command_stats`.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
