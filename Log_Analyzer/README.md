# Анализатор логов — практика 9

Перезапуск на C++17. Всё, что умел анализатор на практике 8, перенесено
и выражено классами. Версия на C (практика 8) остаётся отдельным архивом —
эталоном поведения.

## Что сделано

Главные по заданию — два класса. `LogRecord` — запись: время, уровень,
модуль, текст; разбирает строку журнала (`parse`), печатает себя одной
строкой (`print`), сравнивает себя с другой записью по времени
(`is_earlier_than`). `LogBook` — журнал: хранит записи в `std::vector`,
сообщает их число (`count`), отдаёт запись по номеру (`at`), печатает
сводку (`print_summary`).

Остальное из практик 1–8 тоже стало классами:

| Класс | Что хранит | Что умеет |
|---|---|---|
| `Timestamp` | упакованное время | собрать из частей, разобрать, напечатать, сравнить, час |
| `LevelFilter` | маску уровней | разрешить уровень, все или ни одного, проверить, напечатать |
| `LogView` | указатели на записи | порядок просмотра по времени, уровню, модулю |
| `LogStats` | счётчики | записи по уровням, часам и модулям |
| `LogGenerator` | — | тестовый журнал, тот же, что у версии на C |
| `Shell` | журнал, фильтр, порядок просмотра | выполняет команды |

Команды те же, что в версии на C: `load`, `bsave`, `bload`, `gen`, `count`,
`head`, `tail`, `stats`, `hours`, `modules`, `order`, `view`, `span`, `sort`,
`grep`, `module`, `between`, `since`, `level`, `filter`, `time`, `help`,
`quit`. Новая команда `summary` печатает сводку из задания; она же
печатается при запуске с файлом.

Не перенесены `cost` (сравнение сортировки указателей и записей —
опыт практики 5) и `stress` (загрузка и освобождение по кругу): время жизни
объектов — тема практики 10.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/logan sample.log
> stats
> level error fatal
> head
./build/logan
> gen big.log 100000
> load big.log
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

Файл из аргумента, который не открылся, — ошибка запуска: сообщение уходит
в поток ошибок, и программа завершается с кодом 1.

## Проверка

```
File: sample.log
Lines: 205, records: 200
Lines that could not be parsed: 4
By level: DEBUG 57 INFO 86 WARN 27 ERROR 24 FATAL 6
Earliest record: 2026-03-01 02:13:32
Latest record:   2026-03-28 06:03:21
```

Сценарий из пятидесяти команд — генерация, загрузка, все выборки и отчёты,
фильтр, оба порядка просмотра, сортировка и двоичный поиск, двоичное
сохранение и чтение, ошибки аргументов — дал вывод, совпадающий с версией
на C строка в строку. Строки со временем выполнения в сравнение не входили.
Файлы, созданные `gen` и `bsave` обеими версиями, совпадают байт в байт.

| Случай | Ответ |
|---|---|
| Двоичный файл, оборванный на сотом байте | `the data is corrupted`, прежний журнал цел |
| Чужая сигнатура или неизвестная версия | `invalid format` |
| `bload` текстового журнала | `invalid format` |
| Несуществующий файл при запуске | `Error: cannot open the file`, код 1 |

Всё прогнано под санитайзерами адресов и неопределённого поведения —
без ошибок.

## На что обратить внимание при разборе

**Чем класс отличается от структуры C.** В C запись — данные, а `parse_line`
и печать записи — отдельные функции, получающие запись параметром. Здесь
функции стали методами: `record.parse(line)`, `record.print()`. Поля закрыты,
и испортить запись снаружи нельзя — только прочитать через `level()`,
`module()`.

**Что такое `this`.** Объяснено в `LogRecord::is_earlier_than`. Вызов
`a.is_earlier_than(b)` компилятор превращает в вызов обычной функции,
которой скрытым первым параметром передан адрес `a`. Этот адрес и есть
`this`.

**Состояние оболочки — поля объекта.** На практике 8 фильтр был локальной
переменной `shell_run`, а порядок просмотра — статическими переменными
модуля `view`. Здесь и то и другое — поля `Shell`, и методам команд
не нужно получать их параметрами.

**Один цикл на три выборки.** На практике 7 условие выборки было
указателем на функцию и указателем `const void *` на её данные. Здесь
`grep`, `module` и `between` вызывают три открытых метода журнала, а те —
один закрытый `print_matching`, который получает вид выборки значением
перечисления. Цикл выборки в проекте по-прежнему один.

**Указатели в векторе.** `LogView` хранит адреса записей внутри вектора
журнала. Когда журнал перечитан или отсортирован, записи переехали,
и вид сбрасывается — как `view_reset` в версии на C.

**Памятью управляют стандартные классы.** Текст сообщения — `std::string`,
массив записей — `std::vector`. Ручных `malloc` и `free` больше нет.
Файл открывает `std::ifstream` и закрывает его сам при выходе из метода.
Как это устроено, разберём на практике 10.

**`swap` вместо копирования.** `load_binary` читает во временный вектор
и при успехе обменивается с ним содержимым: записи не копируются,
меняются только указатели на блоки памяти.

**Методы, определённые в классе.** Короткие методы доступа определены
прямо в объявлении класса. Длинные — в `.cpp` с указанием класса:
`bool LogRecord::parse(...)`. Если забыть `LogRecord::`, получится свободная
функция, и компоновщик не найдёт метод.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
