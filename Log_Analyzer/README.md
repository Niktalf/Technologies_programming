# Анализатор логов — практика 1

Эталонное решение первой практики темы «Анализатор логов»: каркас программы,
которая читает журнал построчно и отвечает на простые команды.

## Что сделано

- Имя файла журнала передаётся аргументом; без аргумента программа печатает
  подсказку по запуску и возвращает 1.
- Отсутствующий файл даёт сообщение и ненулевой код возврата, а не аварийное
  завершение.
- Файл читается за один проход: считаются строки, запоминаются первые десять
  и последние десять.
- Интерактивный режим принимает команды `count`, `head`, `tail`, `help`, `quit`.
- Неизвестная команда даёт подсказку и работу не завершает.

В комплекте лежит `sample.log` на 25 строк для быстрой проверки.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/logan sample.log
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## На что обратить внимание при разборе

**Кольцевой буфер.** Последние десять строк хранятся в массиве из десяти
элементов: новая строка занимает место самой старой по остатку от деления
номера на размер буфера. Весь файл в память не читается. При выводе используется
тот же остаток, и это вторая половина задачи: с записью справляются почти все,
с выводом в правильном порядке заметно реже.

**Слишком длинные строки.** Строка, не поместившаяся в буфер, дочитывается
до конца и учитывается отдельным счётчиком. Без этого её хвост стал бы
самостоятельной строкой, и счёт оказался бы неверным.

**Последняя строка без перевода строки.** `fgets` возвращает её как обычную
строку, поэтому счёт не ошибается на единицу. Проверка `!feof(file)` не даёт
принять такую строку за обрезанную.

**Коды ошибок с первой практики.** Здесь они введены раньше программы курса:
без них открытие отсутствующего файла не отличить от пустого файла.

**Одно условие выхода из цикла.** Конец ввода и `quit` сводятся к флагу
`running`, пустая строка — отдельная ветка цепочки. В цикле нет ни `break`,
ни `continue`.

**Два потока вывода.** Ошибки запуска идут в `stderr`, ответы на команды —
в `stdout`.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
