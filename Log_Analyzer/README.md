# Анализатор логов — практика 13

Продолжение проекта двенадцатой практики. Условие отбора стало значением.
Одна функция отбора принимает условие и возвращает подходящие записи.
Все фильтры — лямбды, условие можно сохранить в переменную и применить
к любому источнику. Всё, что умел анализатор на практике 12, осталось.

## Что сделано

**Тип условия** (`include/record_filter.hpp`):

```cpp
using Predicate = std::function<bool(const LogRecord& record)>;
```

Условие получает запись по константной ссылке и отвечает «да» или «нет».
Ни менять запись, ни печатать оно не должно.

**Функция высшего порядка `select(book, condition)`** возвращает указатели
на подходящие записи, а не копии. В ней единственный цикл отбора
во всём проекте. На практике 12 у журнала было три метода выборки
и перечисление `Selection`, чтобы они обошлись одним циклом. Теперь
их нет: журнал только отдаёт записи константными итераторами
`begin()` и `end()`.

**Подсчёт без списка.** `count_matching(book, condition)` — это
`std::count_if` по журналу: ни одной копии и ни одного указателя.

**Четыре фильтра — лямбды с захватом по значению:**

| Функция | Лямбда | Захват |
|---|---|---|
| `by_levels(levels)` | уровень проходит фильтр | `[levels]` |
| `by_module(name)` | модуль совпадает без учёта регистра | `[module]` |
| `by_text(word)` | подстрока в тексте без учёта регистра | `[word]` |
| `between(from, to)` | время в интервале, обе границы включительно | `[from, to]` |

К ним `any_record()` — лямбда без захвата — и `both(first, second)`:
функция, которая принимает два условия и возвращает третье.

`grep`, `module`, `between`, `head`, `tail` и `count` теперь выражены
через `select` или `count_matching` и склеивают своё условие с фильтром
уровней через `both`.

**Условие в переменной.** У оболочки есть поле `Predicate saved_`.

- `cond level error fatal | module net | grep timeout | between ... | any`
  сохраняет условие, `cond` без слов показывает его.
- `match` — записи загруженного журнала по сохранённому условию.
- `match from <источник>` — сколько подходящих записей в любом источнике:
  в файле, в нескольких файлах, в генераторе.

Для этого появился отчёт `MatchReport`. Он хранит копию условия и считает
подходящие записи в том же цикле `run_reports`, что и команда `report`.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/log_analyzer demo/sample.log
> cond level error fatal
> match
> gen g.log 5000 7
> match from files g.log demo/sample.log
> cond module net
> match from random 1000 3
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## Проверка

Сценарий из сорока команд практики 12 дал ровно тот же вывод. В нём
`head`, `tail` и `count` с фильтром уровней, `grep` и `module` с разным
регистром, `between`, `since`, сортировка, отчёты, `bsave`, `bload`
и `gen`. Двоичный файл совпадает байт в байт.

Сохранённое условие `module net` на одном и том же журнале из 5000 записей
даёт 841 и через `match from file g.log`, и через загруженный журнал.
На двух файлах — 877 из 5200. `cond` с неизвестным уровнем или без слова
поиска условие не меняет. Всё прогнано под санитайзерами адресов,
неопределённого поведения и утечек — без ошибок.

## На что обратить внимание при разборе

**Новый фильтр — одна строка.** Например, «текст длиннее 40 символов»:
`[](const LogRecord& r) { return r.text().size() > 40; }`. Цикл писать
не нужно.

**Захват по значению.** `by_module` закончится раньше, чем условие
применят, и её параметр исчезнет. Поэтому `module` копируется в лямбду.
`[&module]` оставил бы сохранённое условие со ссылкой на исчезнувшую
строку.

**Лямбда с захватом — объект с полями.** `[levels]` хранит копию фильтра
уровней. Поэтому `cond level error`, сохранённое до `level all`, и после
него ищет только ошибки.

**Указатели, а не копии.** `select` возвращает `const LogRecord*`. Копии
на миллионе записей заняли бы столько же памяти, сколько сам журнал.
Указатели годны, пока журнал не заменён. Поэтому результат `select` живёт
только внутри одной команды.

**Условие не печатает.** Если бы условие печатало найденное, то
`count_matching` напечатал бы то, что должен был только посчитать.

**`both` — функция, которая принимает функции и возвращает функцию.**
Второе условие не спрашивается, если первое уже ответило «нет».

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
