# Анализатор логов — практика 8

Продолжение проекта седьмой практики: общее перечисление кодов ошибок,
структуры вместо наборов параметров и собственный двоичный формат журнала.

## Что сделано

- Модуль `status`: общее перечисление кодов ошибок и функция перевода кода
  в сообщение. Все функции, способные не справиться, возвращают код из него.
- Дата и время собраны в структуру `DateTime`.
- Модуль `binlog`: сохранение разобранного журнала в двоичный формат
  с сигнатурой и версией и загрузка из него. Испорченный файл даёт ошибку.
- Модуль `query`: выборки, вынесенные из оболочки.
- Новые команды: `bsave <файл>`, `bload <файл>`. `load` печатает время разбора.
- Всё из практик 1–7 работает как прежде.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/logan
> gen big.log 1000000 9
> load big.log
> bsave big.bin
> bload big.bin
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## Проверка

Замер на журнале в миллион записей, сборка `-DCMAKE_BUILD_TYPE=Release`:

```
> load big.log
Parsed in 0.471 s
> bsave big.bin
Saved 1000000 records in 0.104 s
> bload big.bin
Read 1000000 records in 0.149 s
```

Двоичная загрузка втрое быстрее разбора текста. После `load` и после `bload`
команды `head`, `tail`, `stats`, `modules`, `hours`, `sort`, `view`, `grep`
печатают одно и то же — проверено сравнением вывода.

| Испорченный файл | Ответ |
|---|---|
| Текстовый журнал вместо двоичного | `invalid format` |
| Другая версия формата | `invalid format` |
| Файл, оборванный на середине | `the data is corrupted` |
| Число записей 10¹² в заголовке | `the data is corrupted`, ничего не выделено |
| Уровень 77 в записи | `the data is corrupted` |
| Несуществующий файл | `cannot open the file` |

Под адресным санитайзером, который ищет и утечки, чисто на всех испорченных
файлах.

## На что обратить внимание при разборе

**Общее перечисление кодов ошибок (задания 2 и 3).** Модуль `status`
заводит `LogStatus` с шестью кодами из задания — успех, нехватка памяти,
файл не открыт, неверный формат, повреждённые данные, неверный аргумент —
и седьмым, ошибкой записи: место на диске может кончиться при уже открытом
файле, и это не «файл не открыт». Код переводит в сообщение одна функция
`status_text`. На этот код переведены все функции, способные не справиться:
загрузка текста и двоичного журнала, сохранение, генератор, разбор строки
(формат или нехватка памяти — разные исходы), добавление записи, обе
сортировки и построение просмотра. Функции, которые отвечают на вопрос,
а не могут сломаться, — `level_from_word`, `logfile_time_range` — остались
с обычным значением: «такого уровня нет» и «журнал пуст» — это ответы.

**Структура вместо набора параметров (задание 1).** Шесть полей даты
и времени собраны в `DateTime`. Раньше `timestamp_pack` принимала шесть
чисел, а распаковка возвращала через шесть указателей; теперь одна структура
по адресу туда и одна по значению обратно. Разбор момента из командной строки
и печать времени переехали в модуль `timestamp` и больше не повторяются
в оболочке.

**Модули (задание 5).** Разбор — `parse`, хранение — `logfile`, запросы —
`query`, `sort`, `view`, ввод и вывод — `binlog`, коды ошибок — `status`.
Выборки `grep`, `module`, `between` переехали из оболочки в `query`.

**Ни один результат работы с файлом не игнорируется.** Генератор проверяет
каждый `fprintf` и результат `fclose` — часть ошибок записи видна только
при закрытии. `logfile_load` проверяет `ferror` после цикла чтения:
для `fgets` ошибка чтения выглядит как конец файла.

**Почему двоичный быстрее, а не меньше.** Двоичный файл на миллион записей
даже на 23 процента меньше текстового: основное место занимают сами сообщения,
а они и там и там хранятся как есть. Выигрыш не в размере, а в том,
что не нужно разбирать строку на поля и переводить время из текста в число.
Это полезный вывод: двоичный формат — не всегда намного «компактнее»,
но почти всегда «быстрее».

**Строка пишется как длина и байты.** Иначе при чтении невозможно понять,
где она кончается. Завершающий нуль в файл не пишется: длина уже известна.

**Проверка числа записей до выделения.** Испорченные восемь байт иначе
превратятся в запрос на терабайт.

**Журнал меняется только при успехе.** Чтение идёт во временный журнал,
и прежний освобождается лишь после того, как весь файл прочитан.
Поэтому неудачное чтение не оставляет вас ни с чем.

**Что освобождать при ошибке на середине.** Если чтение сорвалось после
того, как текст записи уже выделен, его надо освободить вручную: в журнал
он ещё не попал, и журнал за него не отвечает. Чтение заголовка, одной
записи и всех записей — отдельные функции, которые просто возвращают код;
файл закрывается в одном месте.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
