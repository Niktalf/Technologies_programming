# Анализатор логов — практика 10

Продолжение проекта девятой практики. Класс-владелец файла, загрузка
журнала в конструкторе, поведение при исключении, перемещение. Всё, что
умел анализатор на практике 9, осталось.

## Что сделано

`FileReader` владеет открытым файлом: конструктор открывает и при неудаче
возбуждает `LogError`, деструктор закрывает. У класса все пять особых
методов: копирование запрещено, перемещение передаёт файл другому объекту.
Других способов закрыть файл у класса нет, и в программе нет ни одного
`fclose` вне деструктора.

`LogBook` получает содержимое через конструктор: `LogBook book(path)`.
Отдельного `load` больше нет — объект либо создан и наполнен, либо
не создан вовсе. Двоичный журнал читает `LogBook::from_binary(path)`
и возвращает новый журнал по значению. Сам журнал хранит только векторы
и строки, поэтому особых методов ему не нужно — правило нуля.

`LogError` — исключение с кодом ошибки. Оболочка ловит его и печатает
те же сообщения, что и раньше.

Команды `load` и `bload` строят новый журнал и перемещают его в оболочку:
`book_ = LogBook(path)`. Если файл не открылся, прежний журнал остаётся —
в версии на C и на практике 9 он к этому моменту был бы уже очищен.

Новые команды: `demo` — пять опытов со временем жизни на файле загруженного
журнала, `stress [n]` — n раз загрузить и уничтожить журнал.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/logan sample.log
> demo
> stress 100
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

Файл из аргумента, который не открылся, — ошибка запуска: сообщение уходит
в поток ошибок, и программа завершается с кодом 1.

## Проверка

Вывод `demo`, опыты 3 и 5:

```
3. An exception in the middle of reading:
  [FileReader] opened sample.log
  throwing an exception at line 3
  [FileReader] closed sample.log
  caught: error at line 3
  open files: 0 - the destructor closed the file during stack unwinding

5. Moving the owner: the file is closed exactly once:
  [FileReader] opened sample.log
  [FileReader] moved sample.log to a new object
  after the move, open files: 1
  [FileReader] closed sample.log
  after the block, open files: 0
```

Сообщение `closed` напечатано раньше, чем `caught`: деструктор сработал
при раскрутке стека, до того как исключение дошло до `catch`.

Сценарий из тридцати пяти команд дал ровно тот же вывод, что практика 9,
двоичные файлы совпадают байт в байт. `stress` на журнале в 100 000 записей:
открытых файлов после всех циклов 0, пиковое потребление памяти 33 МБ после
одного цикла и 35 МБ после двух, десяти и ста. Рост между первым и вторым
циклом — не утечка: освобождённую память распределитель оставляет программе
для следующих выделений. Утечка росла бы с каждым циклом. Всё прогнано
под санитайзерами адресов, неопределённого поведения и утечек — без ошибок.

## Где в версии на C терялся бы файл

Откройте `src/binlog.c` из архива практики 8, функцию `binlog_load`.
Между `fopen` и `fclose` нет ни одного `return`: проверки заголовка
вынесены в `read_header`, которая файлом не владеет, а результат всех шагов
собирается в одну переменную `status`. Файл закрывается, но держится это
только на дисциплине. Допишите после `read_header` проверку
`if (count == 0) { return LOG_ERR_FORMAT; }` — и пустой файл останется
открытым, а компилятор ничего не скажет. У себя ищите то же: `return` между
`fopen` и `fclose`.

В `LogBook::read_until_failure` выход посреди чтения есть, а `fclose`
нет — и не нужен.

## На что обратить внимание при разборе

**Исключение из конструктора.** Если конструктор `FileReader` возбудил
исключение, объект не считается созданным, и деструктор для него не
вызывается. Закрывать нечего.

**Почему копировать нельзя, а перемещать можно.** Копия получила бы тот же
`FILE *`, и два деструктора закрыли бы один файл дважды. Перемещение
отдаёт `FILE *` новому владельцу и обнуляет его у прежнего: в опыте 5 файл
закрывается ровно один раз.

**Правило нуля для журнала.** `LogBook` владеет только векторами и строками.
Копирование и перемещение, созданные компилятором, копируют и перемещают
векторы — писать ничего не нужно. Особые методы пишет только тот класс,
который владеет ресурсом сам.

**`book_ = LogBook(path)`.** Справа — временный объект. Присваивание
выбирает перемещение: векторы записей переезжают в `book_`, а не копируются.
Если конструктор бросил исключение, присваивания не было, и `book_` прежний.

**Деструктор не возбуждает исключений.** Он может вызываться как раз
во время раскрутки стека от другого исключения, а второе исключение
в этот момент немедленно завершает программу. Ошибку чтения сообщает
`read_line`, а не деструктор.

**Файл закрывается до конца конструктора журнала.** `reader` — локальная
переменная конструктора `LogBook`. Журнал живёт дольше, чем файл.

**Счётчик открытых файлов.** `FileReader::open_count` — статическое поле:
одно на все объекты класса. Им удобно доказывать, что после ста циклов
незакрытых файлов нет.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
