# Анализатор логов — практика 14

Продолжение проекта тринадцатой практики. Пять аналитических запросов
к журналу выражены через фильтрацию, преобразование и свёртку. Новая
команда `insights` печатает их все. Сводка `summary` тоже переписана
на алгоритмы. Всё, что умел анализатор на практике 13, осталось.

## Что сделано

**Пять запросов** (`include/log_insights.hpp`):

| Запрос | Как выражен |
|---|---|
| Доля ошибок | `count_matching` с предикатом «ERROR или FATAL» — filter и reduce одним `std::count_if`, без списка |
| Десять самых шумных модулей | группировка словарём `unordered_map` за один проход, затем `std::partial_sort` — упорядочиваются только первые десять |
| Средний интервал между ошибками | filter (`select` ошибок), map в секунды (`std::transform`), `std::sort`, пары соседей — `std::adjacent_difference`, reduce — `std::accumulate` со второго элемента |
| Самый загруженный час | 24 счётчика за один проход `std::for_each`, затем `std::max_element` |
| Число различных модулей | `std::transform` имён прямо во множество `unordered_set` |

**Средний интервал при нуле и одной ошибке.** Интервалов на один меньше,
чем ошибок. При нуле и одной ошибке их нет, и функция возвращает `false`
вместо деления на ноль.

**`Timestamp::seconds()`** — секунды от 1970 года по настоящему календарю.
`value()` для интервалов не годится: упаковка считает в каждом месяце
31 день. С ней между 28 февраля 23:00 и 1 марта 01:00 прошло бы три дня
и два часа, а не два часа.

**`summary` без накопителей.** Число записей каждого уровня — `std::count_if`.
Первая и последняя по времени запись — `std::minmax_element` за один
проход. Так же переписан `time_range`, его использует команда `span`.

## Цикл или алгоритм

Обычным циклом каждый запрос выглядел бы так: переменная-накопитель,
цикл по записям, `if` внутри, обновление накопителя, после цикла —
деление или поиск. У среднего интервала таких циклов было бы три:
отбор, сортировка, сумма разностей со счётчиком «предыдущий». Записанные
алгоритмами запросы не короче в строках. Но каждая строка говорит, что
делается: отобрать, превратить, сложить. Ошибкам с накопителем — забыли
обнулить, начали минимум с нуля, разделили в целых, пропустили первый
элемент — просто негде появиться. Где нужна группировка, словарь
заменяет вложенный цикл и делает запрос линейным. Цикл остаётся честным
выбором там, где действие не укладывается в «отобрать — превратить —
свернуть»: печать, разбор файла, построение уровня.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build
./build/log_analyzer demo/sample.log
> insights
> gen big.log 100000 3
> load big.log
> insights
```

Компилятор GCC или Clang собирает проект с `-Wall -Wextra -pedantic`
без предупреждений.

## Проверка

На `demo/sample.log`:

```
Errors (ERROR and FATAL): 15.00% of 200 records
Mean interval between errors: 78918.07 s (1315.30 min)
Busiest hour: 01:00-01:59, 16 records
Distinct modules: 6
```

Средний интервал совпал с расчётом на Python по тем же 30 ошибкам:
78918,069 с. Журнал с ошибками 28 февраля 23:00 и 1 марта 01:00 даёт
7200 с. На журналах с одной ошибкой, без ошибок и на пустом
печатается «fewer than two errors, no intervals», деления на ноль нет.

Сценарий из сорока команд практики 13 дал ровно тот же вывод, в том числе
`summary` и `span`. Всё прогнано под санитайзерами адресов,
неопределённого поведения и утечек — без ошибок.

## На что обратить внимание при разборе

**Начальное значение свёртки.** Сумма интервалов — с `0LL`: секунды
за годы в `int` не помещаются. Свёртка начинается со второго элемента
результата `adjacent_difference`: первый — не интервал, а сам момент.

**`minmax_element` вместо свёртки.** Самое раннее время свёрткой пришлось
бы начинать с наибольшего возможного момента, а не с нуля. У
`minmax_element` начального значения нет вовсе: он начинает с первой
записи.

**Словарь не хранит порядок.** После группировки модулей их нужно
упорядочить. Для десяти из тысячи хватает `std::partial_sort`. При равном
числе записей модули идут по алфавиту — иначе ответ зависел бы
от хеш-таблицы.

**Множество не зависит от порядка.** Число различных модулей — размер
множества имён. Переставь записи — множество то же.

**Предикат «ошибка» один на два запроса.** Он только отвечает и ничего
не печатает.

## Язык вывода

Всё, что программа печатает, — на английском: сообщения, подсказки, справка.
Комментарии в коде — на русском. Так вывод читается в любой консоли,
в том числе в консоли Windows, где кириллица в UTF-8 без настройки
превращается в нечитаемые символы.
